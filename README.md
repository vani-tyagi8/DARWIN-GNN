# Devign Class-Imbalance Study

This project implements the controlled experiment described in the research synopsis:
one fixed Devign-based GGNN, three vulnerability datasets, and five training conditions.

## Experiment matrix

- Datasets: Devign, ReVeal, Big-Vul
- Strategies: baseline, random oversampling, random undersampling, class-weighted BCE, focal loss
- Metrics: precision, recall, F1, MCC, PR-AUC, and confusion-matrix counts
- Recommended seeds: 42, 1337, 2026

Sampling is applied only to the training split. Validation and test sets are never resampled.
Early stopping uses validation PR-AUC; the test set is evaluated once using the best checkpoint.

## Expected processed format

Put each dataset under `data/processed/<dataset>/` as `train.json`, `valid.json`, and
`test.json`. Each file must contain JSON objects with either conventional keys:

```json
{"node_features": [[0.1]], "graph": [[0, 0, 0]], "target": 1}
```

or the `saikat107/Devign` aliases `features`, `structure`, and nested `label`.
Each edge is `[source_node, edge_type, destination_node]`.

## Install and run

```bash
python -m venv .venv
.venv/Scripts/activate
pip install -e ".[dev]"
devign-experiment --dataset devign --strategy baseline --seed 42
pytest
```

## Verified smoke-test data

The public `epicosy/devign` repository includes a 994-function, AST-only sample.
Convert a small stratified subset and run it as follows:

```bash
python scripts/convert_epicosy_sample.py --input-dir ../epicosy-devign/data/input --limit 60
devign-experiment --config configs/smoke.yaml
```

The converter writes `provenance.json` with `purpose: smoke_test_only`. These results
validate software execution but are not valid results for the final multi-edge experiment.

Linux/Colab activation uses `source .venv/bin/activate`. CUDA is selected automatically.
All outputs are written to `runs/<dataset>/<strategy>/<seed>/`, including the best
checkpoint, metrics JSON, and per-example probabilities.

Run the full 45-run study with:

```bash
python scripts/run_matrix.py
```

Use `--skip-existing` when resuming an interrupted matrix. On Google Colab, first run
`bash scripts/setup_colab.sh`; it preserves Colab's CUDA-enabled PyTorch installation.
On Windows, install CUDA-enabled PyTorch using the command generated by the official
PyTorch selector, then install this package with `pip install -e ".[dev]"`.

For the current Windows/Python 3.12 setup, the included helper installs and verifies the
official CUDA-enabled PyTorch wheel:

```powershell
& ".\scripts\setup_windows_gpu.ps1"
```

Prepare the first full dataset, inspect its distribution, and run a single baseline:

```powershell
& ".\.venv\Scripts\python.exe" scripts\prepare_public_datasets.py --dataset devign
& ".\.venv\Scripts\python.exe" scripts\analyze_dataset.py data\processed\devign
& ".\.venv\Scripts\devign-experiment.exe" --config configs\default.yaml --dataset devign --strategy baseline --seed 42
```

See `docs/DATASETS.md` for authoritative sources and acceptance criteria, and
`docs/EXPERIMENT_PROTOCOL.md` for the frozen scientific protocol.

After the matrix completes, generate mean/std tables and per-dataset comparison plots:

```bash
python scripts/plot_results.py
```

For an RTX laptop, begin with one smoke run and reduce `batch_size` if CUDA runs
out of memory. The full Big-Vul matrix is best run one condition at a time so every
completed checkpoint remains recoverable.

## Scientific controls

- Generate dataset splits once and reuse them for every strategy.
- Deduplicate and group related pre-fix/post-fix functions before splitting.
- Fit node-feature vocabularies/embeddings on training data only.
- Do not tune thresholds or hyperparameters on test data.
- Run all dataset/strategy combinations with the same seed set and architecture.
